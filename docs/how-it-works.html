2Alur kerja dari goal sampai PR

Label butuh Anda = berhenti dan menunggu persetujuan.

  1. Goal dan rencana Orchestrator

    Stack belum jelas → tanya 7 pertanyaan satu per satu. Tulis Goal dengan 3 target angka (latency, LCP/INP/CLS, SLO; boleh N/A — alasan), pecah jadi task kecil dengan kriteria terukur, tulis Contracts sebelum FE/BE mulai.

    BOARD.mdGoal · Contracts · Tasksminta izin commit per task, sekali saja

  2. Siapkan tempat kerja Orchestrator

    Buat branch dari base terbaru, lalu satu file task per task dari templat.

    feat/T-01-logintasks/T-01.md

  3. Kerjakan FEBE paralel bila independen

    Klaim task → cek pemicu skill → kerjakan di scope sendiri sesuai Contracts → jalankan lint/tes → commit hanya file sendiri (git add <path>) → status in_review.

    commit T-01: …SHA dicatat di Work Log, bukti perintah + hasil

  4. Review Reviewer

    Baca git show <sha>, jalankan code_quality_analyzer, security-review bila pemicunya cocok. Ada temuan → masuk Fix Loop (bagian 3). Tidak ada → APPROVED.

    R-T01-1 [BLOCKER|MAJOR|MINOR]file:line + saran perbaikan

  5. Tes Tester

    Tulis tes yang membuktikan kriteria penerimaan plus kasus negatif utama, jalankan pada HEAD branch. Gagal → Fix Loop yang sama. Lulus → task done.

    Test Resultsperintah · lulus/gagal · F-T01-n

  6. Sinkron dengan origin Orchestrator

    Semua task selesai → git pull origin <base> ke branch. Konflik diperbaiki oleh role pemilik file (FE, BE, atau Tester); file di luar semua role menunggu Anda. Tester jalankan ulang tes, Reviewer hanya meninjau diff penyelesaian.

    tanpa rebase / force-push

  7. PR dan review PR AndaReviewer

    Push dan gh pr create menunggu persetujuan Anda. Setelah PR ada, Reviewer membaca gh pr diff, selalu menjalankan security-review, lalu memposting satu review COMMENT berisi ringkasan dan komentar inline di baris tiap temuan. Perbaikan di-push ke branch PR setelah Anda setuju.

    push + buka PRpush perbaikan

  8. Laporan akhir dan berhenti Orchestrator

    Format ADHD: apa yang sekarang jalan, X/Y selesai, bukti tes, satu langkah berikutnya. Reviewer tidak pernah approve atau merge; merge tetap milik Anda.

    merge PR

3Fix Loop: temuan kembali ke pembuatnya

Berlaku untuk review task, kegagalan tes, dan review PR. Reviewer dan Tester tidak pernah memperbaiki kode.

open→ Owner memperbaiki, commit baru T-01: fix R-T01-1 →fixed→ Reviewer cek git diff prev..fix →verified
fixed→ perbaikan salah →open ·  MINOR bolehwontfix+ alasan; BLOCKER/MAJOR wajib diperbaiki
putaran ke-4→blocked→ Orchestrator eskalasi ke Anda dengan daftar temuan yang masih open
Status task:todo→claimed→in_review→in_test→done
